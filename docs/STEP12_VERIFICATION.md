# 12단계 제작 2 · 실제 요청의 기대값·응답·ID·시각을 한 표로

사용자가 기존 Supabase에서 제작 2 준비 SQL 실행을 완료했다. 새 배포와
A·B의 실제 요청표 실행은 아직 미실행이다. 제작 1의 화면·API·DB 대조와 구분한다.

## 실행 순서

1. 기존 Supabase SQL Editor에서 `sql/step12-verification.sql` 전체를 실행한다.
   기존 `step12-operations.sql` 준비가 먼저 되어 있어야 한다. 새 전용 시험표와
   제한 함수만 추가하고 기존 메모·승인·사본·감사·작전실 요약을 보존한다.
2. 마지막 결과의 `schema: aleph.verification-setup.v1`, `ready: true`,
   `clientCanRun: false`, `serverCanRun: true`를 확인한다. 사용자가 위 값이
   모두 일치하는 실제 결과 JSON을 제공했다.
3. 새 코드 배포가 확인된 뒤 기존 승인된 B에서 새로고침한다. 작전실의
   **이 계정의 통합 검사 실행**을 누른다. 서버가 각 고정 요청을 한 건씩
   실제 HTTP로 전송하고 실제 응답 ID·확인 시각을 저장한다.
4. 첫 불일치나 응답 실패에서 중단한다. 남은 항목은 미실행이다. 같은 검사
   묶음의 첫 관찰을 재시도로 덮어쓰지 않는다. 수정 후에는 새 묶음으로 검사한다.
5. **저장된 검사 기록 다시 읽기**로 같은 DB 묶음을 읽어 표와 펼친 JSON을
   대조한다. SQL Editor에서도 해당 run_id의 rows를 조회해 독립적으로 대조한다.
6. A도 별도 승인된 로그인에서 같은 순서로 확인한다. 새 로그인은 11단계의
   관리자 승인이 필요하다. 계정·세션·커밋이 다른 기록은 서로 섞지 않는다.
7. 실행하지 않은 수동 시험은 미실행으로 유지한다. 12단계 최종 저장점과
   묶음은 제작 3과 실제 사용자 확인 뒤 진행한다.

자기·상대 메모 읽기 검사는 먼저 두 고정 시험 메모가 각각 A·B 소유로

전제 미충족으로 제외한다. 사본 검증은 B 전용이며 A에서는 계정 제외다.
일반 CRUD의 새 재실행과 실제 복구·실제 회수는 이 자동 목록에 포함하지 않는다.

## 미실행 수동 시험과 기대값

- 새 미승인 세션의 GET /api/notes: 403 DEVICE_APPROVAL_REQUIRED.
- 별도 연습 세션 승인 철회 뒤 GET /api/notes: 403 DEVICE_APPROVAL_REQUIRED.
- A가 B 지정 ID로 POST /api/restore: 404 NOT_FOUND.

각 항목은 자동 표에 미실행으로 남긴다. 수행할 때는 별도의 로그인·승인·
사전 사본 확인 순서와 실제 응답을 기록한다. 현재 승인 세션을 임의로
철회하거나 기존 B 메모를 변경하지 않는다. 과거 실측과 이번 실측을 구분한다.

## 증거와 출처

`GET/POST /api/operations-check`는 승인된 A·B만 사용할 수 있다. 브라우저는
새 묶음 시작 또는 고정 caseId 실행만 요청한다. 임의 URL·소유자·통과 수·
응답·시각을 제출할 수 없다. 서버가 보낸 자기 원본 API 요청의 응답에서
HTTP 상태와 알려진 오류·형식을 확인하고, 반환된 요청 ID를 읽는다.
ID가 없으면 새 ID를 지어내지 않고 불일치로 기록한다.

기존 API는 Vercel 또는 Supabase의 응답 요청 ID를 사용하고, 가상 규칙
API는 자체 응답 헤더와 본문의 같은 UUID를 대조한다. checkedAt은 서버가
응답을 확인한 UTC 시각이다. 메모 제목·본문과 인증값은 표·DB·로그에서 제외한다.
개별 검사 결과는 전용 DB 표의 첫 관찰로 저장하고 같은 객체를 반환한다.

`POST /api/operations-rule`은 고정된 가상 요청/사건만 기존 decide·detect에
전달한다. 응답 출처는 student_fixture_api이다. 실제 운영 엔진 사건 전달,
하드웨어 확인, 실제 재인증·회수 집행을 시험했다고 표시하지 않는다.
판정기 요청 18개·응답 5개와 탐지 사건 3개 필드 계약을 보존한다.

자체 목록은 자동 21항목·별도 수동 3항목이다. 운영 측의 공식 41종 목록이
아니며 41종 통과 수로 환산하지 않는다. 공식 결과는 별도로 미실행이다.
