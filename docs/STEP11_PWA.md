# 11단계 제작 1 · 설치 화면과 오프라인 안내 준비

이 문서는 로컬 제작 기록이다. 11단계 완성·실제 기기 승인·설치 실측 결과가 아니다.

- manifest에 앱 이름·시작 주소·아이콘·독립 창 표시를 설정했다.
- 설치 UI는 설치 상태만 표시하며 로그인·기기 승인을 변경하지 않는다.
- 기기 표시는 `서버 확인 기능 준비 중`이다. 현재 계약에 없는 승인 값을 임의로 만들지 않는다.
- 서비스 워커는 공개 오프라인 안내 한 파일만 저장한다. `/api` 요청은 처리하지 않고 로그인 응답·메모·브라우저 토큰을 캐시에 넣지 않는다.
- 기존 로그인·소유자 검사·구역 API·복구·판정기 응답 계약은 이 변경에서 수정하지 않았다.

## 현재 확인 범위

- 사용자가 변경 전 배포의 새 시크릿 창에서 A로 로그인해 자기 가상 메모가 보이는 것을 확인했다.
- 10단계는 사용자가 재제출 후 통과를 확인했다. 이전 README의 판정 대기 문구는 당시 기록이다.
- `node --test test/pwa.test.mjs`: 5개 통과. 오프라인 안내만 저장하는지, API·인증·메모를 캐시하지 않는지와 설치 UI가 승인을 바꾸지 않는지를 모의 환경에서 확인했다.
- `npm test`: 기존 111개와 새 시험 5개, 총 116개 통과.
- `npm run build -- --local`: 성공. `git diff --check`: 오류 없음. 실제 브라우저·배포 시험을 대신하는 결과는 아니다.
- 실제 브라우저 설치·오프라인 화면·배포 후 정상/거부 재시험은 아직 실행하지 않았다.

## 제작 2에서 확인할 사항

현재 `docs/DECIDER_REQUEST.md`에는 엔진이 확인한 `deviceRegistered`는 있지만, 승인 요청·승인 결과 조회·현재 브라우저와의 연결을 수행하는 API 규격은 없다. `request.device.approval` 등 새 입력을 임의로 추가하지 않는다.

승인 결과의 신뢰할 수 있는 출처와 기기 연결 방식을 확정한 다음, 승인 전 화면 숨김과 최종 API 차단을 함께 구현해야 한다. 설치 완료나 요청 버튼만으로 승인 처리하지 않는다.
